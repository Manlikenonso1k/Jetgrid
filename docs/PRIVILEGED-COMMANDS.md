# Every privileged command JetGrid can execute

> `App\Services\Privilege\CommandRegistry`. Do not edit by hand.

This is the complete list. `CommandRunner` refuses any key that is not here,
and every `{placeholder}` is validated against an exact pattern before the
command is built. Arguments are passed to the process as an **array**, never
through a shell, so no argument value can introduce a second command.

## How to read this

- **Write** commands are refused entirely while `JETGRID_READONLY=true`, and
  refused for adopted/protected resources in every mode.
- **Read** commands run in every mode. Discovery and monitoring use only these.
- **Root** indicates the command appears in the generated sudoers file.

## Write commands (14)

### `nginx.reload`

```
sudo /bin/systemctl reload nginx
```

- **Root:** yes (in sudoers)
- **Why:** Apply a new managed vhost. Only ever reached after nginx.test passes (safety constraint #5). Reload, not restart, so live sites keep serving.

### `nginx.enable_site`

```
sudo /bin/ln -sfn {vhost} /etc/nginx/sites-enabled/{sitename}
```

- **Root:** yes (in sudoers)
- **Why:** Enable a JetGrid-created vhost. Both paths are constrained to the jetgrid- prefix, so an existing site symlink cannot be named.
- **Argument patterns:**
  - `vhost` — `#^/etc/nginx/sites-available/jetgrid-[a-z0-9][a-z0-9._-]{0,60}$#`
  - `sitename` — `/^jetgrid-[a-z0-9]([a-z0-9._-]{0,60}[a-z0-9])?$/`

### `nginx.disable_site`

```

```

- **Root:** yes (in sudoers)
- **Why:** Disable a JetGrid-created vhost. The pattern makes it impossible to name a non-JetGrid site.
- **Argument patterns:**
  - `sitename` — `/^jetgrid-[a-z0-9]([a-z0-9._-]{0,60}[a-z0-9])?$/`
